# MapSliceStreaming — Architecture

## 1. 개요

MapSliceStreaming은 Unity 6.3 LTS와 URP를 기반으로 제작한 모바일 오픈 월드 기술 데모입니다.

핵심 목표는 전체 월드를 항상 메모리에 적재하는 대신, 플레이어의 이동 위치에 따라 필요한 Terrain 청크를 동적으로 관리하고 로딩되지 않은 영역도 시각적으로 자연스럽게 표현하는 것입니다.

프로젝트는 크게 월드 스트리밍, 리소스 관리, Terrain·식생 렌더링, 캐릭터 가림, 지도·경로 안내, 에디터 도구로 구성됩니다.

## 2. 시스템 구조

| 구성 요소 | 책임 |
|---|---|
| Streaming Controller | 플레이어 주변 청크의 로딩·해제 요청 관리 |
| Chunk / Slice Data | 월드 청크의 위치 및 데이터 참조 |
| Addressables Integration | 비동기 에셋 로딩과 리소스 해제 관리 |
| Terrain Renderer | 로드된 청크의 Terrain 및 식생 표현 |
| Distant Forest Renderer | 미로드 청크의 원거리 숲 표현 |
| LOD System | 거리와 화면 크기에 따른 나무 메시 선택 |
| Character Occlusion | 캐릭터를 가리는 식생의 국소적 시각 처리 |
| Navigation System | 미니맵, 전체 지도, 목적지 및 경로 표시 |
| Editor Tools | LOD 생성, 데이터 검사, 설정 및 복구 |

## 3. 청크 기반 월드 스트리밍

### 설계 목적

오픈 월드의 모든 Terrain과 식생을 한 번에 로드하면 모바일에서 메모리 사용량과 초기 로딩 비용이 증가할 수 있습니다.

이를 완화하기 위해 월드를 여러 청크로 구분하고 플레이어의 위치에 따라 필요한 영역을 관리합니다.

### 처리 흐름

1. 플레이어의 현재 위치를 확인합니다.
2. 위치를 바탕으로 필요한 청크 집합을 계산합니다.
3. 아직 로딩되지 않은 청크에 대해 로딩을 요청합니다.
4. 로딩이 완료된 청크의 Terrain과 관련 오브젝트를 표시합니다.
5. 필요 범위를 벗어난 청크에 대해서는 해제 처리를 수행합니다.
6. 로드되지 않은 원거리 영역은 별도 표현 시스템으로 처리합니다.

이 과정에서 중복 로딩 방지, 로딩 완료 시점 확인, 리소스 소유권과 해제 순서가 중요합니다.

## 4. Addressables 리소스 관리

Addressables를 사용하여 청크 관련 에셋을 비동기로 관리하는 구조를 적용했습니다.

리소스 관리에서는 로드 성공 여부뿐 아니라 이후의 해제 정책까지 함께 고려해야 합니다.

특히 비동기 작업이 진행되는 동안 플레이어가 이동해 청크의 필요 상태가 바뀌는 경우를 고려할 필요가 있습니다.

### 주요 검증 사항

- 동일 청크의 중복 로딩 요청 여부
- 비동기 로딩 실패에 대한 예외 처리
- 로드 완료 이후 참조 및 인스턴스 관리
- 청크 해제 시 Addressables 핸들 관리
- 장시간 이동 시 리소스 누적 여부

Addressables의 리소스 해제 호출이 즉각적인 전체 메모리 반환을 의미하지는 않으므로, 실제 메모리 상태는 Profiler로 검증해야 합니다.

## 5. 원거리 숲과 청크 경계

로드된 청크와 아직 로드되지 않은 청크 사이에 숲이 끊겨 보이지 않도록 원거리 대체 렌더링을 사용합니다.

초기 구현에서는 삼각형 기반 나무 프록시를 사용했지만, 실제 나무로 전환할 때 실루엣 차이가 크게 발생했습니다.

후속 구현에서는 실제 나무 에셋의 저해상도 LOD 메시를 원거리 표현에 활용했습니다.

이 방식은 실제 나무와 원거리 나무의 형태 차이를 줄이는 것을 목표로 합니다.

청크가 로드되거나 해제되는 시점에는 원거리 렌더링과 실제 나무 렌더링의 표시 상태를 조정해야 합니다.

## 6. 캐릭터 가림 처리

나무와 같은 환경 오브젝트가 플레이어 캐릭터를 가릴 때 시야 확보를 돕기 위한 렌더링 기능입니다.

캐릭터와 카메라의 관계, 화면상 가림 영역, 관련 렌더러를 고려하여 나무의 일부 표현을 조정합니다.

캐릭터 가림 시스템은 나무의 LOD 전환과 구분하여 관리합니다.

## 7. 지도 및 경로 안내

미니맵과 전체 지도는 동일한 월드 위치 정보를 기반으로 동작하도록 구성했습니다.

전체 지도에서는 목적지를 선택하고, 지형 기반 이동 경로와 직선거리를 표시합니다.

목적지 변경 및 이동 중 경로 갱신을 고려하며, 플레이어가 목적지에 도착한 경우 경로 안내 상태를 정리합니다.

### 주요 구성

- 플레이어 월드 좌표와 지도 좌표 변환
- 미니맵의 플레이어 위치 및 방향 표시
- 전체 지도 목적지 선택
- 이동 가능 영역을 고려한 경로 계산
- 목적지 변경 및 경로 표시 갱신

## 8. 에디터 도구

개발 과정에서 반복되는 데이터를 손으로 수정하지 않도록 Unity Editor 도구를 활용했습니다.

주요 대상은 나무 프리팹의 LOD 생성과 조정, Terrain 데이터 검사, 경로 격자 생성, 누락된 리소스 참조 점검 및 설정 복구입니다.

반복 작업의 자동화뿐 아니라, 잘못된 설정으로 인한 프로젝트 손상을 방지하는 검사 및 백업 기능을 고려했습니다.

## 9. 설계상 주요 고려 사항

| 영역 | 고려 사항 |
|---|---|
| 스트리밍 | 중복 로딩과 경계 왕복 처리 |
| 메모리 | 에셋 핸들·인스턴스 생명주기 |
| 렌더링 | 원거리 숲과 실제 나무 사이의 시각적 연속성 |
| LOD | 화면상 크기와 모바일 GPU 비용 |
| 셰이더 | 투명 처리, 깊이, 정렬 및 오버드로우 |
| 경로 안내 | 월드 좌표와 지도 좌표의 정확성 |
| Android | 실기기 GPU 호환성 및 프레임 안정성 |
