# MapSliceStreaming — Rendering & Optimization

## 1. 최적화 목표

MapSliceStreaming의 주요 최적화 목표는 모바일 기기에서 넓은 자연환경을 렌더링하면서 시각적 품질과 프레임 안정성 사이의 균형을 유지하는 것입니다.

프로젝트에서는 다음 문제를 주요 개선 대상으로 다뤘습니다.

- 가까운 거리의 나무가 지나치게 단순하게 표시되는 현상
- LOD 전환 시 나뭇잎과 나무 실루엣이 급격하게 달라지는 문제
- 미로드 청크의 단순 프록시와 실제 나무 사이의 시각적 차이
- 나무에 가려지는 캐릭터의 가독성
- Android에서 Terrain 및 식생 렌더링의 안정성

## 2. 5-Level Vegetation LOD

### 구조

실제 자연 에셋을 활용하여 LOD0부터 LOD4까지 다섯 단계로 구성했습니다.

| 단계 | 역할 |
|---|---|
| LOD0 | 근거리 원본 고품질 표현 |
| LOD1 | 근·중거리 디테일 유지 |
| LOD2 | 중거리 경량 표현 |
| LOD3 | 원거리 경량 표현 |
| LOD4 | 매우 먼 거리의 간략한 표현 |

### 문제: 근거리 디테일 손실

LOD 생성 과정에서 잎의 삼각형을 단순히 제거하면 나무의 형태가 부자연스럽게 보일 수 있습니다.

나뭇잎 카드가 부분적으로 사라지면 멀리서뿐 아니라 근거리에서도 구멍이 발생할 수 있습니다.

### 개선 방향

근거리에서는 원본 메시의 품질을 보존하도록 LOD 생성 방식을 조정했습니다.

LOD0과 LOD1에서는 형태 유지를 우선하고, 저해상도 단계에서 점진적으로 메시 복잡도를 줄여 화면상 실루엣이 유지되도록 설계했습니다.

## 3. LOD 전환 거리 최적화

### 문제

실제 게임 화면에서 나무가 멀지 않은 위치에서도 낮은 품질로 변경되는 현상이 확인됐습니다.

### 개선

최고 품질 LOD의 유지 범위를 확대하고 나무 종류별 전환 설정을 조정했습니다.

Unity LODGroup은 단순한 월드 거리가 아니라 화면에서 오브젝트가 차지하는 상대적인 크기를 기준으로 LOD를 전환합니다.

따라서 카메라 FOV, 나무 크기 및 화면 설정에 따라 실제 전환 거리가 달라질 수 있습니다.

### 성능 고려 사항

최고 품질 LOD를 더 먼 거리까지 유지하면 GPU 처리 비용이 증가할 수 있습니다.

Android에서는 프레임 타임, 삼각형 수, 드로우 콜 및 발열을 함께 고려해야 합니다.

## 4. Distant Forest Rendering

### 문제

스트리밍 청크가 로드되기 전, 먼 거리의 나무를 단순한 삼각형 프록시로 표시했습니다.

이 방식은 렌더링 비용이 낮지만 실제 나무와 외형 차이가 컸습니다.

청크가 로드되는 순간 단순한 프록시가 실제 나무로 변경되어 시각적인 팝핑 현상이 발생했습니다.

### 개선

원거리 대체 표현에 실제 나무 에셋의 저해상도 LOD 메시를 재사용하는 방식으로 변경했습니다.

주요 목표는 다음과 같습니다.

- 미로드 청크와 로드된 청크 사이의 나무 형태 차이 감소
- 원거리에서도 수종별 실루엣 유지
- 기존 나무 배치의 위치·회전·크기 활용
- GPU Instancing을 통한 반복 나무 렌더링 비용 관리
- 청크 로딩 상태에 따라 원거리 표현과 실제 나무 표현 전환

### 검증 항목

실제 나무와 원거리 대체 메시의 전환 시점, 중복 렌더링 여부 및 Android GPU 처리 비용을 확인해야 합니다.

원거리 메시의 품질을 높이는 것이 항상 성능 개선을 의미하지는 않습니다.

## 5. Character Occlusion Shader

### 문제

카메라와 플레이어 캐릭터 사이에 나무가 위치하면 캐릭터가 가려져 조작성이 떨어질 수 있습니다.

### 개선

캐릭터를 가리는 나무의 일부 영역을 시각적으로 처리하여 캐릭터의 가독성을 높였습니다.

전용 셰이더와 런타임 제어 코드를 분리하여 가림 효과와 렌더러 상태를 관리하도록 구성했습니다.

### 기술적 고려 사항

**Alpha Clipping**

지정한 임계값에 따라 픽셀을 제거하는 방식입니다. 반투명 처리와는 다른 시각적·렌더링 특성을 갖습니다.

**Alpha Blending**

부드러운 투명 표현을 제공하지만 깊이 처리, 정렬 및 오버드로우 비용을 고려해야 합니다.

**Shader Parameters**

가림 중심, 영역 크기, 효과 강도 등의 제어 값을 런타임 제어 코드에서 전달하는 구조를 활용합니다.

### LOD 시스템과의 분리

캐릭터 가림은 캐릭터의 가독성을 개선하기 위한 기능입니다.

나무의 LOD 전환이나 LOD Cross Fade와는 목적이 다르므로 별도 시스템으로 관리합니다.

## 6. GPU Instancing

반복적으로 등장하는 나무와 원거리 식생을 렌더링할 때 GPU Instancing을 활용했습니다.

동일한 메시와 머티리얼을 공유하는 인스턴스를 효율적으로 렌더링하는 것이 주요 목적입니다.

단, GPU Instancing을 사용한다고 모든 상황에서 자동으로 드로우 콜이나 GPU 시간이 감소하는 것은 아닙니다.

URP SRP Batcher 호환성, 셰이더 설정, 머티리얼 수, 그림자 및 GPU 메모리 비용을 함께 고려해야 합니다.

## 7. Android 실기기 검증

| 지표 | 목적 |
|---|---|
| Average FPS | 전체적인 실행 성능 |
| Frame Time | 순간적인 프레임 지연 분석 |

| Batches / SetPass Calls | 렌더링 제출 비용 분석 |

| Memory Usage | 청크 로딩 후 메모리 관리 |
| Thermal Behavior | 장시간 실행 안정성 |

동일한 Android 기기, 해상도, 품질 설정, 이동 경로 및 카메라 조건에서 비교해야 합니다.
